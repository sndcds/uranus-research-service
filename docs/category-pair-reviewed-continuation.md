# Category Pair Reviewed Continuation

## Background

The category-coverage A/B benchmark consists of 1.506 annotation pairs judged by
two independent machine passes (machine-a, machine-b) using `gpt-5.4-mini-2026-03-17`.
Each pair produces two blind judgments that are classified as `machine_agreed`,
`machine_conflict`, or `machine_uncertain`. Conflicts feed a blind conflict pool for
later Astra adjudication.

The original run (PR #18) stopped at `request_failed_partial` after 27 complete pairs
and a partially-dispatched 28th pair. A single-case repair (PR #19) replaced the
rejected machine-b receipt for pair 27. This document describes the reviewed
continuation contract that merges the original partial run and the accepted repair
into an effective state, then exclusively executes the remaining 1.478 pairs.

## Original partial run

The original A/B execution produced:

```text
completed_pairs = 27
status = request_failed_partial
original_dispatches = 56
retries = 0
usage_priced_cost_usd = 0.08962620
settled_cost_usd = 0.08867055
outstanding_reservation_usd = 0.01526175
```

Pair 27 (annotation `a0c166936ef7233017150f87aad87df5`) had machine-a settled
successfully, but the original machine-b receipt triggered `empty_occurrence_field`
on `venue_accessibility`. The receipt was persisted but not settled. The run halted
append-only with no retry.

The original ledger, journal, receipts, and all artifacts remain byte-identical and
immutable. The continuation contract binds their SHA-256 hashes and fails closed on
any deviation.

## Repair overlay

PR #19 performed a single explicitly-approved repair request:

```text
repair_status = accepted
repair_cost_usd = 0.00210675
repair_usage: input=1927, output=147, cached=0, reasoning=0
effective_completed_pairs = 28
effective_pair_completion = repaired
effective_response_source = repair-v1
repair_reconciliation_status = ready_for_reviewed_continuation
```

The repair receipt is a separate artifact. It is never emitted as an original dispatch.
The original rejected B receipt remains rejected in the original immutable ledger.

## Effective state

The continuation contract distinguishes:

```text
Original Ledger State:
  completed_pairs = 27
  status = request_failed_partial
  original_dispatches = 56

Effective Reconciled State:
  effective_completed_pairs = 28
  effective_status = ready_for_continuation
  repair_dispatches = 1
```

The old ledger is not retroactively rewritten. The effective state is computed from
the frozen original state plus the accepted repair reconciliation.

Frozen order indices:

```text
0..26 = original complete pairs
27 = repaired pair
28..1505 = continuation work
```

No requests for indices 0–27 are ever generated by the continuation.

## Budget reconciliation

The original ledger contains a conservative outstanding reservation of `0.01526175 USD`
for the failed B request. The repair replaced that B logically, costing `0.00210675 USD`.
The originally rejected B request was still billed at `0.00095565 USD`.

Effective continuation accounting:

```text
original settled cost:              0.08867055 USD (55 settled receipts)
original rejected B actual cost:    0.00095565 USD (billed, not settled)
repair actual cost:                  0.00210675 USD
─────────────────────────────────────────────
cumulative actual cost:             0.09173295 USD
effective outstanding reservation:  0.00 USD (old reservation not double-counted)
```

The old reservation remains visible in the original immutable ledger. For the new
effective budget calculation it is not counted again as an open future expense. Both
actually incurred request costs are fully retained.

## Continuation execution

After contract and approval validation, the continuation executes pairs 28..1505.
A separate append-only `ContinuationJournal` tracks all events. The original ledger
is never mutated.

For each pair:

```text
admit → dispatch A → settle A → dispatch B → settle B
```

Budget rule before each pair:

```text
effective actual spend
+ effective outstanding reservations
+ conservative reservation A
+ conservative reservation B
≤ 12.00 USD
```

No budget reset. The cumulative actual cost starts at `0.09173295 USD`.

Provider configuration is unchanged:

```text
model = gpt-5.4-mini-2026-03-17
store = false
reasoning = none
temperature = 0
max_output_tokens = 1200
tools = none
history = none
```

No fallback.

Maximum continuation requests: `1478 × 2 = 2956`.

## Crash handling

The continuation journal is append-only and crash-safe. If the process crashes:

- The journal chain is intact (SHA-256-linked events).
- Saved receipts on disk are reconciled offline on resume.
- No blind resend: if a receipt exists, it is verified, not re-requested.
- Resume requires explicit `--resume` flag.

## Completion

Completion requires:

```text
original complete pairs:     27
repair-completed pair:        1
continuation complete pairs: 1478
────────────────────────────────
effective complete pairs:    1506
effective A judgments = 1506
effective B judgments = 1506
```

Only then may consensus be generated.

## Consensus

At full completion, each pair is classified as `machine_agreed`,
`machine_conflict`, or `machine_uncertain`.

For pair 27, machine-b uses the repair-v1 receipt (not the original rejected B).
All other pairs use their original or continuation receipts.

Outputs:

- `machine-consensus.json`
- `conflict-pool.jsonl` (blind candidate data only; no grades or conflict causes)

## Conflict pool

The conflict pool contains only blind candidate data for non-agreed pairs. No A/B
grades, no conflict type, no conflict cause. This pool feeds a future Astra
adjudication contract.

## Safety

- Original journal never rewritten.
- Original receipt never replaced.
- Repair receipt never emitted as original dispatch.
- No already-completed request resent.
- No Pass C.
- No Astra (separate later contract).
- No reevaluation.
- No automatic repair of new evidence failures.
- No global repair-validator leak to normal requests.
- `semantic_query = false`.
- Fail closed on any frozen binding deviation.
- Single attempt per request; no retry on 429/5xx/network/refusal/schema/evidence.
- Append-only on failure; no automatic recovery.
